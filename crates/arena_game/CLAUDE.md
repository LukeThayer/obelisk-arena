# `arena_game` — architecture (post netcode-feel overhaul + levels-and-lobby + weapons + wisp weapon ports)

`arena_game` is a 1v1 online wizard duel: **Bevy 0.18.1 + Avian3d 0.5 + lightyear 0.26.4**, with combat owned by `obelisk-bevy`. It is **server-authoritative** with **lightyear-native client prediction of BOTH players** (design: `docs/superpowers/specs/2026-07-05-netcode-feel-overhaul-design.md`): `PredictionTarget::to_clients(All)` + `InputConfig { rebroadcast_inputs: true }`, so every client simulates the opponent's Dynamic body from their rebroadcast inputs at the local predicted tick — **nothing is interpolated** (the `.add_linear_interpolation()` registrations stay as the documented fallback to the interpolated+lag-comp architecture). Movement is a Dynamic-body FORCE controller (`shared_controller.rs`) driven by native `ActionState<ArenaInput>`. **Casts ride the input stream**: a cast is the falling edge of `ArenaInput.charging`; the server derives the charge byte from held ticks and the aim ray from the input's yaw+pitch — there is no cast message.

**Game flow (levels-and-lobby design, `docs/superpowers/specs/2026-07-06-levels-and-lobby-design.md`):** players spawn into the LOBBY — an editor-authored level — the first joiner still connected is the HOST, and the host starts a PvP match by picking an arena level (`G` panel → `StartMatchMessage`). World geometry is LEVEL DATA (`assets/scenes/*.scn.ron`, authored in `bevy_modal_editor` via `arena-editor`), loaded by `arena_sim::level` on every peer — there is no hard-coded floor anywhere.

> GONE (stale if referenced): the pre-migration hand-rolled netcode (`NetworkedPosition`, `PlayerInputMessage`/`InputChannel`, `prediction.rs`, `replication.rs`, `materialize_replicated_players`, `LinkStart`) AND the feel-overhaul deletions: `CastRequestMessage`, `CastChannel` (now `RequestChannel`, customize-only), `CastIntent`, `ChargeState.pending_charge`, `CustomizeBroadcast`, `InterpolationTarget`, `materialize_interpolated_players`, `send_cast_requests`, `drain_cast_requests`, `drain_customize_broadcasts`, `trace_received_net_events`.

## Crate + binary layout

- `crates/arena_game/src/` — the shared lib (`lib.rs` re-exports `client`, `net`, `server`, `shared_controller`, `skills`, `trace`).
- `crates/arena_game/src/bin/` — `arena-server` (headless authority), `arena-client` (windowed by default; `ARENA_HEADLESS=1` → headless), `arena-observer` (thin alias to `client::run_headless_client`).
- `crates/arena_game/src/net/cue.rs` — the engine-neutral cue wire type (`CueMessage`, `CueKind`, `EndReasonWire`, pure `cue_event_to_message`). The old cosmetic-binding crate this replaces is gone entirely — client cue *rendering* (C3) resolves each fired cue's `obelisk_bevy::assets::CueBinding` from the caster's skill's loaded `CastTimeline` (keyed by the wire's own `skill_id`) and spawns it via `bevy_effect`'s `EffectLibrary`, falling back to `bevy_vfx`'s `VfxLibrary` — see `client/cosmetics.rs`.

## Load-bearing plugin composition order

Identical on server (`bin/server.rs`) and windowed client (`run_windowed_client`, `client/app_windowed.rs`); get it wrong and you get a `PhysicsSchedulePlugin already added` panic or replication that silently never flows.

1. Base plugins + `Time::<Fixed>::from_hz(60.0)`. Server/headless: `MinimalPlugins` + `LogPlugin` + `AssetPlugin` + `TransformPlugin` + `MeshPlugin` + `ScenePlugin` (avian's collider cache needs the asset/mesh/scene plugins even with no rendering). Windowed: `DefaultPlugins` with `AssetPlugin.file_path = <root>/assets`.
2. **lightyear net stack FIRST** — `ServerNetPlugin`/`ClientNetPlugin`, which add `ProtocolPlugin` + `TracePlugin`. Then reapply `ConnectTo`/`ServerBind` from `parse_addr_args(default)`.
3. `add_avian_with_lightyear(&mut app)` **after** the net stack — the *sole* avian `PhysicsPlugins` registrant (`lib.rs:54`).
4. obelisk sim: `add_obelisk_sim_headless` (server) / `add_obelisk_sim_client` (client) — both **omit `ObeliskSpatialPlugin`** (else the physics group double-adds and panics). The client variant additionally omits `ObeliskCombatPlugin` + `detect_overlaps` (Stage A).
5. obelisk config/effects/skills + `seed_combat_rng(session_seed())` (server) / `seed_combat_rng(1)` (client, never drawn).
6. Server: `skills::register_server_cue_egress` + `ArenaServerPlugin`. Client: `bevy_vfx::VfxPlugin` + `bevy_effect::EffectPlugin` (both windowed-only — the headless client adds neither), controller/present/parts/customization/hud plugins, `ClientNetPlayerPlugin`, frame-interpolation, cue-binding + predicted-cast + event-trace, input bridges.

## Netcode: connection → spawn → replication

1. Server boots; `spawn_server` triggers **`Start`** (`net/server.rs:70`). `Start` (not `LinkStart`) adds the `Started` component that `Replicate::on_insert` hard-requires to register newly-spawned entities to already-connected clients; with only `LinkStart`, the first player never replicates to its own client.
2. Each new client link (`On<Add, LinkOf>`) gets `ReplicationSender::new(33ms, SinceLastAck, false)` (`net/server.rs`, `REPLICATION_SEND_HZ=30`) — NOT `default()`.
3. On `On<Add, Connected>`, `spawn_player_on_connect` (`server/spawn.rs`) spawns ONE obelisk combatant per client: `make_combatant(StatBlock::with_id("player_{id}"))` + `Faction` (slot 0 → `Player`, else `Enemy`) + the STARTER weapon equipped (`equip::queue_equip` — item stats via `StatBlock::equip`, `SkillSlots` rewritten, replicated `EquippedWeapon`) + a CHILD `Hurtbox` sensor + the networked component set (+ `ActionState<ArenaInput>` + `PrevCastInput`) + `RigidBody::Dynamic` `Collider::capsule(0.35, 0.48)` (rotation locked, friction 0) + `Replicate::to_clients(All)` + **`PredictionTarget::to_clients(All)`** (no InterpolationTarget) + `ControlledBy`. Spawning in the OBSERVER (not a polled system) guarantees the owner's replication sender exists before the targets resolve. The slot comes from this client's position in the SORTED list of currently-connected ids (matches `reset_for_new_round`); the spawn POSITION is the current level's spawn point for that slot (`LevelSpawns`, round-robin), and existing players are RE-placed when a join shifts their slot. The observer also runs host election (`HostState`).
4. lightyear materializes **`Predicted`** entities for BOTH players on EVERY client. `client/net.rs` attaches the Dynamic body to each; the `Controlled` one additionally gets `InputMarker` (input authority) + `LocalNetPlayer`, the remote one a bare `ActionState<ArenaInput>` that lightyear fills from the server-rebroadcast inputs (`receive_remote_player_input_messages`). The opponent is SIMULATED at the local predicted tick — extrapolated through their last-received input on a direction change, corrected by rollback + `CorrectionPolicy` smoothing.

### What replicates (`net/protocol.rs`)
- Identity: `NetworkedPlayer`, `NetworkOwner(client_id u64)`, `NetworkedId(u64)` (stable cross-peer key, the harness correlation key), `ObeliskNetId(String)` (stable combat id).
- Pose: avian `Position` + `Rotation` — predicted (rollback) + linearly corrected (interpolation registrations kept-but-untargeted = the fallback).
- Velocity: `LinearVelocity` + `AngularVelocity` — predicted + rollback only.
- `NetworkedCastState { cast_phase, cast_skill }` — discrete, snapped. Drives the opponent's authoritative cast-phase animation (the charging TELEGRAPH additionally reads the remote's predicted `ActionState.charging` — instant).
- `NetworkedHealth { current: f64, max: f64 }` — discrete, snapped. The HUD source of truth (≤33ms stale at the 30Hz send cadence).
- `EquippedWeapon { item_id, skills }` — the equipped obelisk item + its granted skills IN SLOT ORDER; the single list `ArenaInput.skill_slot` indexes on both peers (cast pipeline server-side, wheel/selection client-side). Discrete, snapped.
- `PlayerCustomization { parts }` — live edits are plain component updates (`SinceLastAck` resends until acked); the old "component updates are unreliable" lore was wrong.
- `NetworkedSkillObject { kind, owner }` — replicated skill objects (portals/tiles/spires); the pose rides the same replicated avian `Position`/`Rotation` as players (spires rise server-side and the client mirror follows). Discrete, snapped; client visuals key off `kind` (`client/skill_objects.rs`).
- Inputs: `ActionState<ArenaInput>` rides the native input plugin's own path (per-tick, redundancy 5 packets, rebroadcast to the other client), NOT component replication.

### Channels + messages (`net/protocol.rs`)
- `RequestChannel` (C→S, reliable): `CustomizeMessage { parts }`, `StartMatchMessage { level }` (host's match start — server-validated), `EquipWeaponMessage { item_id }` (lobby-only weapon swap — server-validated against the `WeaponCatalog`). Casts do NOT ride a channel — they are the input stream's `charging` falling edge.
- `EventChannel` (S→C, reliable): `NetEventMessage` (wraps obelisk `NetEvent`), `CueWireMessage` (wraps `crate::net::cue::CueMessage`), `RoundStateMessage` v2 (phase tag 0 = **Lobby**; + `host: u64` — the elected host's client id, 0 = none; + `level: String` — the loaded level id clients mirror locally).

### Rollback (`net/protocol.rs`)
Per-component `*_should_rollback` with 0.01 epsilons (matches the canonical `avian_3d_character` example). Not reflexive — comparing a value to itself returns false, so only a real `>= 0.01` divergence triggers a rollback. `PredictionManager` carries the explicit (== default) `RollbackPolicy` (state+input Check) and `CorrectionPolicy` (exponential visual-error decay, 50%/200ms); `snap_large_corrections` removes teleport-scale (>2m) corrections so round resets snap. Rollback-replayed FixedUpdate systems with un-managed `Local` state MUST be rollback-guarded (see `local_cast_edge`).

## Movement: prediction + rollback

A Dynamic-body force controller shared verbatim by both peers and re-run by lightyear during rollback. **Both players run it on every client** (the remote from rebroadcast inputs).

1. Input source → `LocalInput` resource: windowed `bridge_windowed_input_to_local_input` (`client/app_windowed.rs`, WASD + `CameraYaw`/`AimPitch`, camera-relative: forward = -Z, strafe = +X in the yaw frame) or headless `automove_input` (`client/app_headless.rs`).
2. `buffer_arena_input` (`client/net.rs`) copies `LocalInput` (+ latches) + `ChargeState` + the `SelectedSkill` slot onto the `InputMarker` entity's `ActionState<ArenaInput>` in `FixedPreUpdate`/`InputSystems::WriteClientInputs` — lightyear samples it there and ships it (per-tick, 5-packet redundancy).
3. Controller execution (FixedUpdate, chained yaw-then-movement on both peers): server `server_apply_yaw`/`server_apply_movement` (`With<NetworkedPlayer>, Without<Predicted>`); client `client_apply_yaw`/`client_apply_movement` (`With<Predicted>` — BOTH players). `apply_arena_movement` accelerates planar velocity toward `move_dir * MAX_SPEED` via avian's `move_towards`, applying `required_acceleration * mass`; a grounded jump applies an upward impulse to reach `JUMP_SPEED`. Yaw is a **separate** system because avian's `Forces` borrows `Rotation` internally.
4. Render smoothing: every Predicted player gets `FrameInterpolate<Position/Rotation>` (`add_frame_interpolation_to_predicted`, `client/harness.rs`); the camera reads the result in PostUpdate after `PhysicsSystems::Writeback`.
5. **Input timing invariant:** the client must run AHEAD of the server far enough that inputs for tick T arrive before the server simulates T — 0.26.4's server-side `InputBuffer::get(tick)` has NO last-value fallback, so a persistently-late client's player FREEZES while everything else works. `InputTimelineConfig`'s 25ms jitter_margin (`net/client.rs`) guarantees ≥1.5 ticks of slack; do not remove it.

Note: movement force is applied **unconditionally of ground state** (full-strength air control); only the jump is ground-gated. Friction is 0 so the controller fully owns planar velocity (releasing input decelerates at the full `MAX_ACCELERATION`).

## Cast pipeline (input-carried, design WS2/WS3)

Combat is 100% server-authoritative (obelisk). Cast INTENT rides the input stream; the client predicts COSMETICS only.

1. `bridge_windowed_cast_hold` (`client/app_windowed.rs`): LMB press sets `ChargeState.charging` + `tap_latch` (sub-tick-tap guarantee); hold accumulates `secs`; release drops `charging`. Headless `autocast` pulses `tap_latch` on a cadence. No message, no intent resource.
2. `buffer_arena_input` samples `charging || tap_latch` per tick into `ActionState<ArenaInput>` — the falling edge IS the cast, visible identically to both peers in the same stream.
3. Server `detect_cast_edges` (`server/cast_pipeline.rs`, FixedUpdate before `ObeliskSet::Validate`): `step_cast_edge` fires on the edge with the slot latched at press + `charge_byte_from_hold_ticks(held)`; aim ray = `net::aim_dir(yaw,pitch)` from the eye (`Vec3::Y*ARENA_EYE_HEIGHT`); `resolve_cast_aim` picks the candidate `CastAim` per the authored `Acquisition`; inserts `PendingCast`; obelisk's `validate_casts` → `resolve_acquisition` does the authoritative range/filter/fallback + mana/cooldown gate, emitting `CastBegan` or `CastRejected`.
4. obelisk FixedUpdate sets resolve the rest: `validate_casts` → `advance_casts` → `move_projectiles` → `detect_overlaps` (hit → `DamageResolved`). Only the server runs `ObeliskSet::ResolveHits`.
5. Egress (`skills.rs`): `capture_cue_event` buffers obelisk `CueEvent`s (resolving `source` Entity → `ObeliskId`, stamping the caster `aim_dir`), `broadcast_cues` ships them as `CueWireMessage`; `egress_net_events` broadcasts `NetEvent` as `NetEventMessage`.
6. Client predicted presentation: `local_cast_edge` (`client/net.rs`, FixedUpdate, rollback-guarded) mirrors the server's edge on the local `ActionState` and emits `PredictedCast { skill_id, source_id, position, aim_dir, charge }`. `predicted_local_cast` (`skills.rs`) plays the `on_cast` cue NOW and schedules each `Scheduled` collision window's `on_window_*` cue at `phase_start(phase)+offset` (`tick_predicted_cues` fires them at the LIVE caster pose) — so your own bolt launches at the authored moment with zero added round-trip. Template (emitter-spawned) windows are NOT predicted. Every predicted cue registers in `PredictedCues`; `cancel_rejected_casts` drops a `CastRejected` cast's unfired queue (fizzle).
7. Client consume: `consume_replicated_cues` (`skills.rs`) is the SINGLE `CueWireMessage` drain — it skips cues found in the `PredictedCues` registry (exact source+cue match, consumed once, 5s expiry) and forwards survivors as `LocalCue`; `OnHit`/`OnEnd`/`OnEmit` and Template-window cues always play (server-authoritative). `spawn_cue_cosmetics` (`cosmetics.rs`, C3) resolves each `LocalCue`'s `CueBinding` and spawns the bound effect via `EffectLibrary`/`VfxLibrary`, flying a `CosmeticProjectile` for `CueAttach::Follow` bindings (the server's `OnEnd` cue tears the predicted one down too — same `end_cue` key). Damage numbers come from the `ClientNetEvent` fan-out in `hud.rs`.

## Rig / animation + customization

- **Attach** (`present.rs`): `attach_rig_to_players` hangs the `character.glb` scene (`ArenaBody`, π gltf-yaw, `RIG_FOOT_OFFSET=-0.62`) under every materialized `NetworkedPlayer` + inserts `LocalAnimBlend`. The local body is `LocalPlayerBody` + `Visibility::Hidden` (first-person).
- **Animate** (`rig.rs`): `build_graph_when_loaded` builds one `AnimationGraph` from the glb's named clips. `drive_animation` is **per-player** — it walks the `ChildOf` chain from each `AnimationPlayer` to its owning rig root and drives a locomotion layer (remotes blend from their replicated `LinearVelocity`+`Rotation` yaw; the hidden local rig uses camera yaw + zero velocity) + a casting layer (from `NetworkedCastState.cast_phase`: 1/2 → 1.0, 3 → 0.5, 0 → 0.0, eased; the local player pre-empts to 1.0 while charging).
- **Parts** (`parts.rs`): per-mesh `Visibility` from `PartSelection`. The local rig reads the local `PartSelection` resource (the customizer's edits); each remote rig reads its player's replicated `PlayerCustomization.parts`. Body skin / weapons / capes are categorically hidden.

## Levels (`arena_sim::level` + `server/levels.rs` + `client/level.rs`)

World geometry is editor-authored data: bevy `DynamicScene` RON (`.scn.ron`) saved by `arena-editor` (`bevy_modal_editor`), loaded by `arena_sim::level` on EVERY peer (all peers ship identical files — only the level *id* rides the wire).

- **Catalog**: `LevelCatalog::scan_roots([<root>/assets/scenes, <root>/crates/arena_editor/assets/scenes])` at startup on every peer; id = filename stem; first-root-wins dedup; `"lobby"` is reserved (never host-selectable). Shipped levels: `lobby` (walled court, 4 spawns, lights), `arena_flat` (the legacy-geometry duel arena — its equivalence to the old hard-coded floor/markers is unit-tested).
- **Supported content (v1)**: `SceneEntity` + `Name` + `Transform` + primitives (`PrimitiveMarker` cube/sphere/cylinder/capsule/plane with `MaterialRef` Library/Inline + `RigidBody`), groups, point/directional light markers, and `arena_sim::level::ArenaSpawnPoint { slot }` (palette-insertable in the editor via `register_custom_entity`; match levels need slots 0+1, the lobby any number — placement is round-robin by sorted-client-id index). Anything else fails `preflight_unknown_types` with the offending type paths named.
- **Loading**: `load_level_scene(path)` → `LevelScene { statics, lights, spawns }` in WORLD space (pure data); `spawn_level(commands, &scene, visuals)` spawns colliders + avian `Position`/`Rotation` on every peer, meshes/materials/lights only when `visuals` is passed (windowed client). Everything is tagged `LevelEntity` — the despawn key for switches.
- **Scale is BAKED, never `Collider::set_scale`/Transform scale**: `scaled_collider` bakes the level scale into the collider SHAPE (collider scale stays 1.0) and the visual mesh bakes it into VERTICES (render `Transform` scale stays 1.0). Under the game's composition, lightyear inserts scale-1 `Transform`s on physics entities and avian's collider backend resets collider scale to match — a `set_scale`d floor became a 1m cube and everyone fell through the world (see `tests/level_physics.rs`).
- **Server flow**: `startup_load_levels` loads the LOBBY; `drain_start_match` validates the host's `StartMatchMessage`; `apply_level_switch` performs every switch (despawn `LevelEntity`s → `spawn_level` physics-only → replace `CurrentLevel`/`LevelSpawns` → re-place players). Clients mirror via `RoundStateMessage.level` → `client/level.rs::sync_level_from_round_state`.

## Complex spells: the skill-objects + verbs pattern (wisp weapon ports)

The design seam for spells obelisk can't natively express (design: the wisp potted-spring/portal ports). Content stays PURE obelisk (rules TOML + `.cast.ron`); the arena adds three orthogonal extension points — use these (in this order of preference) before inventing new machinery:

1. **Cue verbs** (`server/verbs.rs`): obelisk fires `CueEvent`s at every authored timeline moment with exactly what a verb needs (author-named cue id, world position, source entity, charge). `skill_verbs_on_cue` matches `(skill_id, cue_id)` → typed arena action. The cue slot MUST be listed in the timeline's `vfx_cues` (that's what makes obelisk emit it — `cues` only binds client visuals). Renaming a window renames its `on_window_<id>` slot and silently kills the verb — `tests/content_wisp_ports.rs` pins the pairs the verb table matches.
2. **Skill objects** (`server/skill_objects.rs` + `client/skill_objects.rs`): ONE generic persistence mechanism for anything a spell leaves in the world (portal discs, frost tiles, spires) — per-kind caps with replace-oldest eviction, lifetimes, optional physics, replicated as `NetworkedSkillObject` + avian pose with kind-keyed client visuals. Adding a kind = a const + a `max_instances` arm + a client recipe (+ optionally a `skill_object_<kind>` vfx preset — no code).
3. **Arena aim validators** (`cast_pipeline::validate_arena_aim`): per-skill gesture gates BEFORE `PendingCast` for aims obelisk's `Acquisition` can't express (frost_spire's "must aim at a tile", snapped to its center). A rejected edge costs no mana (`cast_aim_rejected`).

The glacier chain shows the trigger idiom: `rolling_glacier` (Ballistic lob) --on_impact--> `glacier_roll` (triggered-only; `motion_direction: Horizontal` flattens the inherited BALL travel direction — obelisk `e96110a` passes the ending hitbox's `aim` as the lifecycle payload direction; before that fix every lifecycle-triggered projectile marched world-+X) --on_impact/on_expire--> `glacier_burst` (triggered-only nova). The tile TRAIL is `drop_glacier_trail` POLLING the roll's `Hitbox` — deliberately not an obelisk emitter, because Template windows share the skill's lifecycle triggers (each tile's expiry would re-fire the burst). Triggered-only skills still need BOTH files (`config/skills/` + `assets/skills/*.cast.ron` — `load_cast_timelines` loads every registry id) but are never granted to a weapon.

Portals are FULL Portal-game portals (wisp's `spells/portal.rs` + `server_portal_teleport`, ported whole — see the dedicated section below). Deferrals for the wider wisp ports (documented, deliberate): no glacier snowball growth, no spire chaining, no handheld/moving portals.

## Charge presentation (charge_cues — the designer charge-up surface)

A chargeable skill's HOLD is authored data: `CastTimeline.charge_cues` (obelisk 79882ce) is a list of TIERS `{ threshold, cue }` — while the cast button is held, the highest tier at or below the LIVE charge fraction is active: its effect loops on the caster (usually `CueAttach::Bone` on a rig joint — `R_wrist_joint` is the casting hand), its `anim` clip overlays the rig's casting layer, and its `scale <- Charge` param streams the live fraction into the loop (the glow swells). Crossing a threshold drains the old loop (emission stop, particles age out) and ignites the new one; release drains everything and the ordinary `on_cast` cue takes over. PURE PRESENTATION with ZERO wire traffic: charging rides the replicated input stream, so `client/charge_cues.rs` drives tiers for the LOCAL player (own `ChargeState`) and the REMOTE (predicted `ActionState.charging`) alike — the enemy's hand visibly ignites while they hold. `CueBinding.anim` is also consumed for `on_cast` now (one-shot rig overlay for windup+active), and `CueAttach::Bone` works on cast cues (muzzle flash riding the hand). Sockets resolve per rig via `client/sockets.rs`; the LOCAL player's bone-anchored charge fx live on `SELF_BODY_LAYER` (in-your-face fog first-person otherwise — the HUD charge bar is the local feedback; the fx show through portals + to the opponent). EDITOR: the Skill panel's "Charge (hold)" region edits tiers (threshold %, effect, World/Bone + socket dropdown + offset, anim, grows-with-charge toggle); the preview stage hangs the REAL `character.glb` under the caster (`PreviewCasterRig`, arena_editor registers it) so the bone picker lists real joints and the strip's charge slider live-previews tier crossings on the rig (editor 5cbd133). Harness: `ARENA_AUTOCAST_HOLD=<secs>` scripts held charges (works windowed for shots).

**Hand origination (launch = charge point):** casts LAUNCH from the casting hand, not the eye. `arena_sim::tuning::CAST_HAND_OFFSET` (re-exported from `arena_game::net`; local aim frame +X right/+Y up/−Z forward, matches the `R_wrist_joint` socket) is rotated by the caster's yaw (`net::hand_launch_offset`) and passed as obelisk's `PendingCast.muzzle_offset` — consumed ONLY at window spawn, so projectiles + predicted `on_cast` cues originate at the hand while AIM acquisition keeps the camera-accurate eye ray (`Vec3::Y*ARENA_EYE_HEIGHT`): standard FPS muzzle parallax. The lateral 0.32 stays inside the firebolt-radius+hurtbox overlap band — the net-test's flat-aim hit depends on it. The EDITOR previews the same launch: `arena_editor` registers the constant as `PreviewCasterRig.hand_offset` and the preview stage (editor 94c20cb) rotates it to the stage aim into `PendingCast.muzzle_offset`; preview cosmetics also honor `CueAttach::Bone` (flash rides the rig hand via `RigSockets`).

## Portals (see-through + predicted traversal — the wisp/Portal-proper overhaul)

ALL portal math lives in ONE module — **`portals_shared.rs`** (`PortalPose`, `disc_rotation` (local +Y = surface normal, −Z held toward world-up so the view doesn't roll), `portal_virtual_transform` (anti-parallel X-flip, one-sided ground-exit +Y clamp), `portal_camera_transform` (the mirrored vantage BEHIND the exit), `velocity_rotation` (anti-parallel Zπ else Xπ flip), `player_crossing` (horizontal discs: segment sign-flip; vertical discs: the PRESSED-BAND rule — |along| entering `WALL_TRIGGER_ALONG` 0.45, since a capsule against a solid wall can never sign-flip), `projectile_crossing` (sign-flip), `in_floor_slab`, `collect_pairs` (COMPLETE per-owner orange+blue pairs, owner-sorted), all tuning consts, 9 unit tests) — because THREE consumers must agree bit-for-bit:

1. **Server authority** (`server/portals.rs`): `portal_floor_passthrough` (before the physics step: a player inside a floor-portal slab (radial < 1.4, |along| < 2.0) whose disc isn't in its lockout drops `Ground` from its `CollisionLayers` filter — it FALLS INTO the disc; the exit disc stays solid until the lockout clears at 2.1 so you stand where you emerged), `refresh_portal_passthrough` (publishes live discs into `arena_sim::obelisk::PortalPassthrough` — `report_world_hits` skips impacts inside a disc, so projectiles FLY THROUGH portal-bearing surfaces instead of bursting on them), `portal_teleport` (after the step: players via the virtual transform + wall→floor `EXIT_STAND_OFFSET`, velocity through `velocity_rotation`; projectiles remap `Transform` + `Hitbox.aim` + **`Projectile.velocity`** + reset `LastHitboxPos` so the next world-hit segment doesn't span the warp). ANY body travels through ANY complete pair (Portal semantics — not owner-gated).
2. **Client prediction** (`client/portals.rs`, registered by `ClientNetPlayerPlugin` → runs headless too): the SAME two systems over the `Predicted` bodies (BOTH players — the opponent's crossings predict from rebroadcast inputs) with client-local prev/lockout state, ROLLBACK-GUARDED (the maps aren't rollback-managed; a skipped replay resolves to the server's answer). **THE SEAMLESSNESS INVARIANT** (Portal's defining property, pinned by the `teleport_continues_the_through_view` unit test): the teleport mapping IS the through-view camera mapping — identical rotation everywhere, positions coinciding at the disc plane — so walking in continues exactly the perspective the disc was showing. The LOCAL player's predicted teleport snaps the FULL camera (`CameraYaw` via `yaw_from_forward` AND `AimPitch` via `pitch_from_forward`) to the mapped forward, DEBOUNCED 0.3s (`CAMERA_SNAP_DEBOUNCE_SECS`: a mispredicted crossing can rollback and legitimately re-cross, and a second view snap reads as a wild spin; positions/velocity still teleport). The next input tick carries the new yaw, turning the server body to match. Remote-player crossings are BEST-EFFORT predictions — the owner's camera snap flips its input yaw mid-crossing, so the opponent's copy often resolves via the server rollback snap instead (`snap_large_corrections` — reads as an instant clean warp). NO per-pair special cases: a `pair_preserves_heading` floor-pair carve-out was tried and REMOVED — it broke through-view continuity, which is the actual spec.
3. **Render** (`client/skill_objects.rs`, windowed): each replicated portal disc gets a `PortalMaterial` (`assets/shaders/portal.wgsl` — samples its texture in SCREEN SPACE + a rim tint) + a dedicated off-screen `Camera3d` (`RenderTarget::Image`, order −1, fov 90°, texture ≤ 1280, layers `[0, SELF_BODY_LAYER]`) driven every frame by `portal_camera_transform` from the `FollowCamera` viewer, with the OBLIQUE near-clip plane set to the exit disc plane (Lengyel; native `PerspectiveProjection::near_clip_plane` in bevy 0.18) so the wall back / entry disc never leak into the through-view. Camera inactive until the pair completes; orphan cameras despawn with their disc. Portal-through-portal shows the previous frame (one-bounce recursion, wisp behavior). **You can see yourself through a portal**: the local body's meshes live on `present::SELF_BODY_LAYER` (1) — invisible to the layer-0 main camera, rendered by the portal cameras (wisp's SELF_BODY_LAYER split; requires `disable_skinned_mesh_culling`, see present.rs).

**Placement** (`server/verbs.rs`): raycast from the caster's eye along its live `ArenaInput` aim (range 15, excluding caster + hurtbox child + all skill objects) → stick to ANY surface (0.02 inset, `disc_rotation(normal)`), or float in the AIR at 2.5 facing back on a miss. Cap 1 per color per caster; recasting moves the disc. The skill timelines are plain `Aim` acquisition — the mark window is a `strikes:false` cue carrier.

**Collision-layer invariant**: level statics are `GameLayer::Ground` (`arena_sim::level::spawn_level`), player bodies are `GameLayer::Player` with ALL filters at BOTH spawn sites (`arena_sim::spawn::make_arena_combatant` server-side, `client/net.rs::materialize_predicted_players` client-side) — the floor pass-through toggles exactly the Ground bit and the two peers MUST stay identical or prediction desyncs while standing in a slab.

## Round machine + lobby flow (`server/rounds.rs` + `server/levels.rs`)

Server-owned FSM (`RoundState`/`RoundPhase`), broadcast as `RoundStateMessage` on the reliable `EventChannel`:

`Lobby` (in the lobby LEVEL; exits ONLY via an accepted host `StartMatchMessage` — never by player count) → `Countdown(3s)` → `Active` → `RoundOver(2s, winner)` → next `Countdown`, or `MatchOver(6s)` once a player reaches `ROUND_WINS_TO_MATCH = 2` — then everyone returns to the LOBBY (level switch + zeroed scores).

- **Host**: first joiner still connected (`HostState`, CONNECT order — a different ordering from the sorted-id spawn/faction slots, deliberately). Re-elected on disconnect; broadcast in `RoundStateMessage.host`; only the host's start requests are honored.
- `detect_round_end` reads obelisk's `EntityDied` stream **only during `Active`**, collecting **all** deaths that tick (pure `round_outcome` helper): a single death credits the *survivor*; a same-tick **double-KO is a draw** (replay the round, credit no one) instead of crediting an arbitrary corpse; a stray non-player death leaves the round running. It still drains the stream in other phases so a stale death isn't mis-attributed.
- `run_round_machine` advances by real time and runs `reset_for_new_round` on the Countdown→Active rising edge: heal to max life/mana, clear effects, `interrupt_cast`, **re-assert each player's `Faction` by sorted client-id slot** (`faction_for_slot`), teleport both to the CURRENT level's spawn slots (position + authored facing), zero `LinearVelocity`. The Position reset replicates; the predicted owner rolls back to it. A mid-duel disconnect (player_count < 2) in `Active`/`Countdown`/`RoundOver` falls back to `Lobby` AND queues the lobby level. The `cleanup_player_on_disconnect` observer (`On<Remove, Connected>`) drops the client from `ClientPlayerMap` + its score entry, re-elects the host, and re-evaluates the phase.
- `broadcast_round_state` sends only when `dirty`, and won't clear `dirty` until at least one sender exists (so the initial state isn't lost pre-connect). Countdown/MatchOver re-broadcasts are throttled to ~1/sec. The message carries `host` + `level` so ONE message moves clients through the whole flow.

Damage stays 100% obelisk-authoritative; this machine only reads deaths and resets state. The HUD renders it via `hud::update_round_label`.

## Key invariants + footguns

1. **Write avian `Position`, never `Transform`.** Spawn/reset set `Position` (`server/spawn.rs:179`, `server/rounds.rs:432`). `LightyearAvianPlugin` (`AvianReplicationMode::Position`) owns the `Position`↔`Transform` sync; a `Transform` write gets clobbered and won't replicate.
2. **Trigger `Start`, not `LinkStart`** (`net/server.rs:62-71`). `LinkStart` alone → the first player never replicates to its own client.
3. **`add_avian_with_lightyear` is the ONLY `PhysicsPlugins` registrant.** Both obelisk composers omit `ObeliskSpatialPlugin`; adding it (or `ObeliskSimPlugin`) double-adds the physics group and panics.
4. **Stage A: the client never resolves combat.** `add_obelisk_sim_client` omits `ObeliskCombatPlugin` and `detect_overlaps` — the client must never draw `CombatRng` or spawn a `Hitbox`. Damage is server-only.
5. **Hurtbox lives on a CHILD entity** (`server/spawn.rs:211-218`) so the player root stays `RigidBody::Dynamic`. The child is a `Sensor` capsule with NO `RigidBody`, attached as a compound child collider that tracks the moving body.
6. **Force-refresh the `SpatialQueryPipeline`** (`lib.rs:260`, ordered before `ObeliskSet::Validate` and before `ResolveHits`). Under `LightyearAvianPlugin` the physics-set reshuffle leaves obelisk's spatial reads seeing an EMPTY pipeline — without this, firebolts fly straight through hurtboxes and never resolve.
7. **Trace `extra` fields must not use the key `kind`** — use `cue_kind` etc. The harness merges `extra` over a base object carrying the top-level `kind`, so a `kind` field silently clobbers the event type.
8. **Single-drain rule:** `MessageReceiver::receive()` drains — ONE drain site per message type per app: `CueWireMessage` → `skills::consume_replicated_cues`; `NetEventMessage` → `skills::drain_net_events` (consumers read the `ClientNetEvent` fan-out — the HUD once drained the receiver directly and silently stole events from the trace); `RoundStateMessage` → windowed `hud`, headless `trace_replicated_round_state`; `CustomizeMessage` → server `drain_customize_requests`. A second reader steals messages.
9. **obelisk is the authority** for casts/damage/death; identity correlation across peers uses `NetworkedId`/`ObeliskNetId`, never local `Entity`.
10. **`Collider::capsule(0.35, 0.48)` is duplicated in 3 spawns** (server body `spawn.rs:184`, server hurtbox `spawn.rs:215`, client predicted body `net.rs:231`) and MUST stay identical or prediction/hurtbox desync. Player mass is implicit (avian default density) and intentionally cancels in the controller (`force = accel*mass`, `impulse = dv*mass`) — any future knockback/external impulse must account for this.
11. **Faction is assigned by sorted-client-id slot** (`faction_for_slot`: slot 0 → Player, else Enemy) at connect AND **re-asserted every round** in `reset_for_new_round`. Because the slot comes from the *sorted* id list (not connect order), the two duelists land on slots 0/1 and can NEVER share a faction — a shared faction would make firebolt's `Enemies` filter resolve zero hits and hang the match. Any change to the slot derivation must keep spawn and reset using the *same* sorted-id slot.
12. **Level colliders: bake, never scale.** Level statics get their dimensions baked into the collider SHAPE (`scaled_collider`) and mesh VERTICES — collider scale and `Transform` scale stay 1.0 everywhere. Lightyear inserts scale-1 `Transform`s on physics entities and avian's collider backend resets collider scale to the Transform's; any scaled collider/Transform on a level entity gets stomped (the fall-through-the-world bug, `tests/level_physics.rs`). Relatedly: the hurtbox child's pose is PINNED every tick (`pin_hurtboxes_to_bodies`) because `ColliderTransform` is captured once at attach under this composition — an early teleport froze hurtboxes meters from their bodies and no firebolt could ever hit. The ground check is `grounded_by_ray` (raycast, works on ramps/platforms) — the old flat-floor Y-threshold is gone.
13. **`InputMarker` only on the `Controlled` entity.** The remote predicted player carries a bare `ActionState` (rebroadcast-fed); giving it an `InputMarker` would make this client claim input authority over the opponent.
14. **Rollback replays FixedUpdate.** Any FixedUpdate system with `Local`/side-effect state that must fire once per REAL tick (edges, one-shots, traces) needs the `With<Rollback>` guard (`local_cast_edge` is the template) — the conditioned net-test caught this producing duplicate predicted casts.
15. **Keep the client ahead of the server** (the `InputTimelineConfig` 25ms jitter_margin): 0.26.4's server `InputBuffer::get` has no late-input fallback — a behind-schedule client's inputs are silently never applied (player frozen server-side, everything else fine).
16. **Collision layers are part of the prediction contract.** Level statics = `GameLayer::Ground`, both peers' player bodies = `GameLayer::Player` with ALL filters (server `make_arena_combatant` + client `materialize_predicted_players`); the portal floor pass-through toggles exactly the Ground bit via the SAME shared rule on both peers. A layer mismatch between the peers desyncs prediction whenever someone stands in a portal slab. `PortalPassthrough` (arena_sim) is the world-hit exemption seam — the server refreshes it every tick from the live pairs.

## Net-test harness (`crates/arena_game/tools/net-test/`) — do not break

The objective headless regression gate. `run_session.sh` launches `arena-server` + two `arena-observer` headless clients (the `arena-client` `ARENA_HEADLESS=1` path), each with distinct `ARENA_TRACE_FILE`/`ARENA_TRACE_SRC`. BOTH observers carry `ARENA_AUTOSTART_LEVEL=arena_flat` — whichever the server elected host (handshake-completion order, NOT launch order) starts the match out of the lobby; the other's hook no-ops. Observer-0 (`ARENA_CLIENT_ID=1`, `ARENA_AUTOCAST=1`, `ARENA_AUTOMOVE=1`, `ARENA_CAM_YAW=-1.5707963`) scripts firebolts at observer-1 (`ARENA_CLIENT_ID=2`); `summarize.py` asserts over the merged per-process JSONL that:
- the server emits `server_net_cast_began(caster=player_1)` + `server_net_damage_resolved(caster=player_1, target=player_2)`,
- BOTH observers emit a matching `client_net_cast_began` AND `client_net_damage_resolved`,
- the echoed `total_damage` matches the server's authoritative number.

It resolves obelisk ids from the server's `player_spawned` events (keyed by `client_id`). Knobs: `ARENA_NET_TEST_DURATION` (default 8), `ARENA_MATCH_SEED` (default 42 → deterministic damage), `ARENA_SKIP_BUILD=1`.

**Gate runners:** `summarize.py` (python3, the user's CI) and `check_session.sh` (jq — python3-free dev shells) assert the SAME contract; run `bash crates/arena_game/tools/net-test/run_session.sh <dir>` then `bash .../check_session.sh <dir>`. **`run_conditioned.sh`** runs the identical session at ~100ms RTT + 10ms jitter + 2% loss (via the `ARENA_NET_LATENCY_MS`/`ARENA_NET_JITTER_MS`/`ARENA_NET_LOSS` client conditioner env knobs) — nothing may be LOST under loss, only delayed; run it after any netcode change.

**The gate depends on** (a) the env hooks (`ARENA_AUTOCAST`/`ARENA_AUTOCAST_SKILL`/`ARENA_AUTOCAST_PERIOD`/`ARENA_AUTOCAST_HOLD` (held charges)/`ARENA_AUTOMOVE`/`ARENA_AUTOSTART_LEVEL`/`ARENA_AUTOEQUIP`/`ARENA_CUSTOMIZE`/`ARENA_CAM_YAW`/`ARENA_TEST_PITCH`/`ARENA_CLIENT_ID`/`ARENA_NET_*` — AUTOCAST/AUTOEQUIP/AUTOMOVE are registered on the WINDOWED client too for visual probes; windowed-only: `ARENA_DEBUG_UI=wheel|weapons`, `ARENA_SHOT`/`ARENA_SHOT_FRAME`/`ARENA_SMOKE_FRAMES`), (b) the `trace::event` kinds emitted across the `server/` submodules (`spawn.rs`/`levels.rs`/`cast_pipeline.rs`/`mirrors.rs`/`rounds.rs`/`controller.rs`/`skill_objects.rs`/`verbs.rs`/`portals.rs`), `client/net.rs`, `client/level.rs`, `client/portals.rs`, and `skills.rs` (`player_spawned`, `level_loaded`, `host_elected`, `match_started`, `start_match_sent`, `weapon_equipped`, `equip_weapon_sent`, `server_net_cast_began`, `server_net_damage_resolved`, `client_net_cast_began`, `client_net_damage_resolved`, `materialized_player`, `replicated_player`, `remote_pose`, `remote_input_seen`, `cast_edge`, `cast_edge_sent`, `predicted_cast`, `predicted_cue`, `cue_deduped`, `client_hp`, `client_round_state`, `cast_aim_rejected`, `skill_object_spawned`, `skill_object_expired`, `glacier_tile_drop`, `spire_erupted`, `spire_fizzled_no_tile`, `portal_placed` (+ `normal`/`surface`), `portal_teleport`, `predicted_portal_teleport`, …), and (c) the `arena-observer` alias staying in sync with `run_headless_client`. Renaming/removing any trace kind or env hook, or moving combat resolution to the client, fails the gate.

**Scripted-cast semantics (wisp-ports revision):** `ARENA_AUTOCAST_SKILL` takes a COMMA-SEPARATED list and rotates one entry per pulse (`portal_orange,portal_blue` places the pair; a single id behaves as before). `autocast` stamps `ARENA_CAM_YAW`/`ARENA_TEST_PITCH` onto the input stream itself — a casting observer aims correctly WITHOUT `ARENA_AUTOMOVE` (previously `automove_input` was the only yaw/pitch writer and a non-moving caster silently aimed flat -Z). `ARENA_AUTOEQUIP` paces `ARENA_AUTOSTART_LEVEL`: the host holds its start request until its OWN equip round-trips (equips are Lobby-gated server-side — a start racing the equip stranded the caster on the starter weapon), so scripts equipping from a non-host observer should set `ARENA_AUTOEQUIP` on EVERY observer.
